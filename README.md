# 房源组合最优解计算器

基于 **Tauri 2.0 + Rust + React 18 + TypeScript** 的桌面本地应用，用于计算房源组合的最优解。所有计算在本地完成，不依赖网络。

**当前版本：v0.1.0**（Apple Silicon / arm64）

---

## 项目简介

房产销售场景下，将多种户型房源（如 50㎡、70㎡、90㎡、120㎡、150㎡）打包为不同的"组合方案"销售。用户指定某个组合的销售数量后，系统自动计算其余组合的最优数量，使**剩余房源尽可能少**，并将占用情况以彩色网格直观呈现。

## 功能特性

| 功能 | 说明 |
|------|------|
| 户型管理 | 添加/编辑/删除户型类型与库存数量，实时统计总套数 |
| 组合定义 | 每种组合可配置包含的户型及各户型套数，自动汇总单组合套数 |
| 最优解计算 | 指定任意组合的销售数量（可多选），其余组合自动求最优解 |
| 网格可视化 | 总套数 = 方格数；每种组合独立颜色；未使用房源灰色；逐格亮起动画 |
| 交互反馈 | 计算/渲染期间显示旋转沙漏；悬停格子显示"户型 · 组合" |
| 公平性 | 多最优解时自动选择组合数量方差最小的均衡方案 |
| 数据持久化 | 户型和组合配置自动保存到本地，重启恢复 |
| 二次确认 | 删除组合有确认弹窗，防止误操作 |

## 使用指南

**三步流程：**

1. **录入房源**：左侧面板添加户型（如 50㎡×20、70㎡×30…），添加后中央网格自动生成对应方格数
2. **定义组合**：添加组合，为每种户型设置套数（如 组合A = 50㎡×1 + 70㎡×2 + 90㎡×1，共 4 套）
3. **指定数量并计算**：在"指定组合数量"输入组合个数（如 组合A = 5），其余组合自动求解最优值

中央网格会按组合着色：组合 A 占多少套房源，就有多少个方格被涂上组合 A 的颜色；灰色方格为剩余房源。右侧面板同步显示各组合分配数量、剩余明细、算法类型与耗时。

## 核心算法

### 问题建模（整数线性规划）

```
目标:  最大化 Σ(xk × 组合k总套数)          （等价于最小化剩余房源）
约束:  ∀户型j: Σ(xk × 组合k中j的套数) ≤ 库存j
       xk ≥ 0 且为整数
```

### 求解链路

1. **扣除手动指定**：先减去用户手动指定的组合占用的房源，校验不超库存
2. **ILP 求解**：使用 `good_lp` + `microlp` 求解剩余组合的最优数量；组合数 > 60 或求解超时（2s）时降级
3. **贪心降级**：多起点贪心（大优先 / 小优先 / 原始顺序 / 轻组合优先 4 种策略取最优），批量分配
4. **公平性均衡化**：在保持总套数（最优值）不变的前提下，通过"总量守恒转移"使各组合数量方差最小，避免单一组合独占

### 可视化映射

- 每个方格 = 一套房源，按户型顺序排列（先 50㎡ 全部，再 70㎡ 全部…）
- 组合着色按户型分配：组合 A 含 50㎡×1 + 90㎡×1、卖 5 个 → 50㎡ 区 5 格 + 90㎡ 区 5 格涂组合 A 颜色
- 着色格数恒等于右侧"已使用套数"，悬停可查看每格归属

## 常见问题

**Q：为什么首次打开提示"无法验证开发者"？**
本地构建未做代码签名，右键 → 打开即可；正式分发需配置 Apple Developer 证书签名与公证。

**Q：浏览器预览和桌面版结果会不一样吗？**
可能。预览用 JS 贪心（近似解），桌面用 Rust ILP（精确解），两者都经过公平性均衡化。桌面版为准。

**Q：组合没设置完就自动计算？**
未完整定义的组合自动跳过（数量记 0），不阻塞其他组合的计算；设置完成后自动重算。
